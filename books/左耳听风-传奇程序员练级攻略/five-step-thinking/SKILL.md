# 五步思考法

## R — 原文 (Reading)

> "第一步：考证信息数据的正确性。第二步：处理集合及其包含关系。第三步：处理逻辑因果关系。确认强因果关系需要分辨充分条件、必要条件和充要条件。第四步：找到可信的基准线。最佳实践和业内标准被很多人长时间验证过。第五步：开启更为深入和高维度的思考。"
>
> — 陈皓, 第5章 有竞争力的程序员

---

## I — 方法论骨架 (Interpretation)

这是一套五步递进的独立思考框架，核心目的是对抗"人云亦云"的快思考本能，用系统方法逐层检验一个主张的可靠性。

1. **信息源甄别**：先问"这条信息从哪来的"——是一手资料还是二手解读？来源是否可靠？如果信息源本身不可信，后续分析毫无意义。
2. **集合包含检验**：检查主张中的概念外延——"A能取代B"的前提是A的适用集合完全包含B，这个包含关系真的成立吗？
3. **逻辑因果检验**：区分充分条件、必要条件和充要条件。很多错误主张的根因是把相关性当成因果性，或把必要条件当成了充分条件。
4. **基准线对标**：找业内公认的标准、最佳实践或大数据来做参照物。一个主张如果和行业基准线偏差很大，要么是革命性的，要么是错的。
5. **高维深入**：前四步验证了"表面是否合理"之后，用追问（如5-Why分析法）深入根因，或从更高维度（历史规律、跨领域类比）审视问题。

整个过程是"慢思考"——调用大脑的系统2，反人性但能超越绝大多数人。

## A1 — 书中的应用 (Past Application)

### 案例 1: 在亚马逊用5-Why分析法追查线上故障
- **问题**: 亚马逊线上系统出现故障，需要写修复报告，但浅层修复只能治标不治本。
- **方法论的使用**: 亚马逊要求在故障修复报告中写明五个"为什么"（5-Why分析），通过不断追问根因迫使员工进行深度思考。作者将此纳入五步思考法的第五步——"高维深入"的核心来源。
- **结论**: 5-Why分析让员工摆脱浅度思考，不断追究问题本质，并为此做大量调查和研究。
- **结果**: 这一实践成为作者五步思考法第五步的来源，后来用于分析各种技术主张和商业论断。

### 案例 2: 抵制日货到出国亲身体验后的世界观转变
- **问题**: 作者年轻时抵制日货、当过"愤青"，持有一套基于二手信息的立场。
- **方法论的使用**: 用第五步"高维深入"的方式——亲身体验替代二手信息。长时间在加拿大、英国、美国、日本等国生活和工作后，用实际观察对标之前的认知基准线。
- **结论**: "有些事情并不是我一开始所认识的那样，甚至截然相反。"
- **结果**: 形成了"亲身去体验这个世界，而不是听别人说"的世界观，后续遇到类似情绪化主张时会建议对方先做信息源甄别和亲身体验。

### 案例 3: 2016年创业选择可观测性产品方向
- **问题**: 创业需要选择产品方向，国内市场上可观测性尚未走热。
- **方法论的使用**: 运用第一步"信息源甄别"——关注国外一手技术前沿而非国内二手讨论。运用第四步"基准线对标"——可观测性在国外已经火了很长时间，是被大量分布式系统实践验证过的需求。
- **结论**: 国内尚未关注可观测性，但国外已经证明了这个方向的价值，时间差意味着先发优势。
- **结果**: 2016年创业做可观测性产品，后来可观测性在国内走热，验证了基于信息源质量和基准线的判断。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户看到一篇技术文章或社交媒体帖子，声称"X将取代Y"或"Z是未来趋势"，需要判断其可信度——比如"Go语言将完全取代Java""微服务已经过时了"。
2. 用户在工作中面对一个技术方案，团队里有人主张A方案、有人主张B方案，双方各有理由，用户需要系统分析而非凭直觉站队。
3. 用户在职业发展上听到某种建议（"35岁必须转管理""应该全栈发展"），不确定是否靠谱，需要用结构化方法检验。
4. 用户在做技术选型，需要在多个竞品之间做判断，不想被营销话术带偏。

### 语言信号 (用户的话里出现这些就应激活)

- "这篇文章/这个说法靠谱吗"
- "我该怎么判断/评估这个说法"
- "别人都说X，但我有点怀疑"
- "这个方案和那个方案到底哪个好，我理不清"
- "我感觉这个结论有问题，但说不出哪里不对"

### 与相邻 skill 的区分

- 与 `deep-learning-trio` 的区别: 本skill是"评判一条已有信息的可信度和深度"，deep-learning-trio 是"从零开始系统学习一个新知识领域"。前者面对的是"别人说的"，后者面对的是"我要学的"。
- 与 `tech-learning-sop` 的区别: 本skill是思考框架，用于判断和推理；tech-learning-sop 是学习SOP，用于系统掌握一项技术。本skill的第4步"基准线对标"会用到 tech-learning-sop 中的"对比"维度。
- 与 `competency-leap` 的区别: 本skill是通用的独立思考方法，competency-leap 是职业竞争力发展路径。本skill的熟练使用是 competency-leap 第一阶段"认知"能力的核心工具。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **信息源甄别 — "这条信息从哪来"**
   - 追问信息的原始来源：是一手资料（原始论文、官方文档、发明者的著作）还是二手解读（公众号、翻译文章、他人转述）？
   - 完成标准: 明确标注信息来源的层级（一手/二手/三手），并列出至少2个可交叉验证的来源。
   - 判停条件: 如果信息来源完全无法追溯，直接标注为"不可验证"，跳到第5步给出"信息源不可信，无法进一步分析"的结论。
   - 输出格式:
     ```
     ## 信息源甄别结果
     | 来源 | 层级 | 可信度 | 备注 |
     |------|------|--------|------|
     | [来源1] | 一手/二手/三手 | 高/中/低 | … |
     | [来源2] | 一手/二手/三手 | 高/中/低 | … |
     **交叉验证**: [2个来源是否互相印证？有无矛盾？]
     ```

2. **集合包含与逻辑因果检验 — "逻辑上成立吗"**
   - 集合检验：检查主张中的概念外延关系。例如"X取代Y"需要X的适用场景完全覆盖Y。
   - 因果检验：区分充分条件、必要条件、充要条件。标注主张中的因果链条，检验每一环是否成立。
   - 完成标准: 列出主张中的核心概念和因果链，标注每一环的逻辑关系类型（充分/必要/充要/相关），指出薄弱环节。
   - 输出格式:
     ```
     ## 逻辑因果检验
     | 因果链环节 | 主张 | 逻辑类型 | 是否成立 | 薄弱原因 |
     |------------|------|----------|----------|----------|
     | 环节1 | "A → B" | 充分/必要/充要/相关 | ✅/❌/⚠️ | … |
     | 环节2 | "B → C" | 充分/必要/充要/相关 | ✅/❌/⚠️ | … |
     **集合包含检验**: [A的外延是否完全包含B？]
     **逻辑薄弱环节**: [最不成立的一环及其原因]
     ```

   ⏸️ **检查点**: 逻辑检验完成后，暂停向用户确认：因果链条的拆解是否完整？是否有遗漏的中间环节？用户对薄弱环节的判断是否认同？确认后再进入基准线对标。

3. **基准线对标与高维深入 — "和行业标准比呢？根因是什么"**
   - 找到业内公认的基准线（最佳实践、行业标准、大数据统计），将主张与基准线对比。偏差大的需要额外论证。
   - 用追问法（至少追问3层"为什么"）深入根因，或从更高维度（历史规律、跨领域类比）重新审视。
   - 完成标准: 给出最终判断（可信/部分可信/不可信/需更多信息），附上基准线对标结果和至少一个高维视角的分析。
   - 输出格式:
     ```
     ## 最终判断
     **主张**: [被分析的主张]
     **判断**: ✅可信 / ⚠️部分可信 / ❌不可信 / ❓需更多信息

     ### 基准线对标
     | 对比项 | 主张内容 | 行业基准线 | 偏差 |
     |--------|----------|------------|------|
     | … | … | … | 大/小/无 |

     ### 5-Why 追问
     1. 为什么…？→ …
     2. 为什么…？→ …
     3. 为什么…？→ …

     ### 高维视角
     [从历史规律/跨领域类比/更高维度得出的洞察]

     **综合结论**: [1-2句话总结判断和理由]
     ```

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **紧急操作场景**: 线上故障正在发生、需要立即行动时，不应花时间做五步分析——先止损再复盘。
- **纯事实查询**: 用户问"Python的GIL是什么"这类有明确答案的问题，直接回答即可，不需要五步分析。
- **个人偏好/价值观选择**: "我该不该出国""要不要创业"这类问题涉及个人价值观，五步思考法可以辅助分析事实层面，但不能替代价值观判断。

### 作者在书中警告的失败模式

- **信息茧房与二手信息陷阱 (ce10)**: 长期依赖二手信息源，信息在传递中失真，建立的知识体系存在系统性错误。五步思考法的第一步"信息源甄别"正是为了对抗这个陷阱——永远追问"这条信息的原始来源是什么"。
- **快餐式学习陷阱 (ce01)**: 被推荐算法驱动的信息流提供了持续的多巴胺反馈，让人误以为"刷到了就是学到了"。五步思考法要求"慢思考"，正是为了对抗这种"快思考"的惯性。
- **迷信标准答案 (ce04)**: 思维被"标准答案"固化，无法进行工程化的独立思考。五步思考法的核心目的就是打破对标准答案的依赖，建立自己的判断体系。

### 作者的盲点 / 时代局限

- 作者的五步思考法基于互联网行业的信息环境，对于传统行业中信息不透明、一手资料难以获取的场景，第一步"信息源甄别"可能难以执行。
- 作者假设"慢思考"总是优于"快思考"，但在某些需要快速决策的场景（如交易、应急），训练有素的直觉可能比系统分析更有效——这一点书中未讨论。
- 存在幸存者偏差：作者用这套方法做出了正确判断（如选择亚马逊、选择可观测性方向），但未展示使用这套方法后判断失败的案例。

### 容易混淆的邻近方法论

- "批判性思维"是一个更宽泛的概念，五步思考法是它的一种具体实现——给出了可执行的五个步骤。
- "第一性原理思考"侧重于从基本假设出发重建认知，五步思考法侧重于对已有主张的逐层验证。两者互补但不等同。
