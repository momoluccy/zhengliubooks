# 淘汰的方法论单元 + 原因

> 阶段1.5三重验证未通过的单元，保留审计轨迹

---

## 1. 三观驱动的选择模型 (原f18)

- **不通过**: V3 独特性
- **原因**: "激进vs保守、长期vs短期"的二元取向框架在任何自助书籍中都能找到，不够独特。虽然作者有个人经历佐证，但框架本身缺乏差异化洞察。
- **降级为**: 金句引用，可在"做正确的事"skill中作为案例

## 2. 人生选择跷跷板模型 (原f17)

- **不通过**: V3 独特性
- **原因**: "不选择的代价大于选错的代价"虽然有道理，但不是反直觉的见解。大多数人生规划类书籍都有类似表述。
- **降级为**: 金句引用，可在"做正确的事"skill中作为A1案例

## 3. 软件开发三层次模型 (原f10)

- **不通过**: V1 跨域（边缘）+ V3 独特性
- **原因**: 只在第2章出现，缺乏跨章节的多处佐证。"面向功能→面向性能→面向智能"的递进不反直觉，是大多数工程师的自然认知。
- **降级为**: 背景知识，可在"技术领导力"skill中引用

## 4. 沟通类比计算机通信框架 (原f13)

- **不通过**: V2 预测力
- **原因**: 虽然将沟通类比为通信过程很有趣，但用这个框架解决实际沟通问题时，得出的结论（要尊重、要倾听、要用数据说话）都是常识级建议。类比是装饰性的，没有真正提升解决方案的质量。
- **降级为**: 有趣的类比，可在"高效沟通"相关内容中引用

## 5. 举一反三三能力模型 (原f12)

- **不通过**: V3 独特性
- **原因**: 联想能力、抽象能力、自省能力的分类是教育学和认知科学的常见分类，不是作者的独特见解。虽然作者有实践案例，但框架本身缺乏差异化。
- **降级为**: 学习方法引用，可在"深度学习三步法"skill中作为"技能转换"环节的具体手段

## 6. T恤估算法 (原f16)

- **不通过**: V1 跨域
- **原因**: 只在第16章出现一次，没有在其他章节中被引用或佐证。作为需求估算法虽然实用，但缺乏全书层面的方法论支撑。
- **降级为**: 具体工具/技巧，可在团队管理相关内容中引用

## 7. 编程本质三要素框架 (原f09)

- **不通过**: V3 独特性（边缘）
- **原因**: Program = Logic + Control + Data 虽然是作者的独特表述，但核心洞察（分离关注点）是软件工程的基础共识。不过这个框架的表述方式很有启发性，适合作为编程实践的指导。
- **降级为**: 保留观察，可在"编程实践"相关skill中作为引用。如果有需要，可在后续迭代中重新评估。

## 8. 技术发展脉络追溯法 (原f22)

- **不通过**: V3 独特性（边缘）
- **原因**: "了解历史才能理解现在"是各学科通用的学习方法，不够独特。但"画出技术演化时间线（C→C++→Java）"的具体做法有一定价值。
- **降级为**: 可在"系统学习技术模板"skill中作为第六维度（与已有实现对比）的具体操作手段

## 9. 3Ps进度更新法 (原f26)

- **不通过**: V1 跨域
- **原因**: 只在第22章（远程工作）出现一次。Plan/Priority/Problem的三要素框架虽然实用，但太轻量，缺乏跨章节佐证。
- **降级为**: 具体工具/技巧

## 10. "1-2-3"问题升级原则 (原f19)

- **不通过**: V3 独特性
- **原因**: 问题升级机制是运维和项目管理的基本实践，"1小时→2小时→3小时→升级"是直觉性的时间递增，不反直觉。
- **降级为**: 远程工作实践技巧

## 11. 个人成长四标准检验法 (原f23)

- **不通过**: V3 独特性
- **原因**: "能否进入一流公司、能否找到稳定工作、能否做大多数人做不到的事、是否有领导力"——这四个标准虽然全面，但每个都是常见的成功标准，组合在一起也不够独特。
- **降级为**: 自我评估清单引用

## 12. 三层自由递进模型 (原f24)

- **不通过**: V3 独特性（边缘）
- **原因**: 工作自由→技能自由→物质自由的递进有一定洞察，但"自由"的分层在财务自由类书籍中很常见。不过"技能自由"（靠技能养活自己不需公司）这一层有一定独特性。
- **降级为**: 可在"职业发展三目标模型"skill中作为第三层"自由"的展开论述

## 13. 中年危机应对模型（投资者vs投机者）(原f20)

- **不通过**: V3 独特性
- **原因**: "做投资者不做投机者"是几乎所有理财/人生规划书籍的核心主张，不够独特。
- **降级为**: 金句引用

## 14. 避免长期妥协的三步框架 (原f21)

- **不通过**: V3 独特性
- **原因**: "找适合的人合作、与智者共事、提高自身能力"是常见的职场建议，不反直觉。
- **降级为**: 可在"做正确的事"skill中作为A2场景的具体行动步骤引用

## 15. 技术决策三步路径 (原f27)

- **不通过**: V3 独特性
- **原因**: "调研→对标→比较优缺点→决策"是标准的决策流程，任何MBA课程都会教。
- **降级为**: 具体实践引用
