# 信息源质量评估方法

## R — 原文 (Reading)

> 挑选信息和知识源需要关注以下几点：一手段位——一手信息通常来自原始论文、官方文档和发明者的著作；可验证性——好的信息有数据和佐证，可以独立检验；时间检验——经过时间考验的信息比追逐热点更可靠；信息密度——好的信息驱使你搜索、学习、沉思、反省、推理、验证和实践。
>
> — 陈皓, 第5章 有竞争力的程序员 / 第8章 高效学习

---

## I — 方法论骨架 (Interpretation)

这是一个用于判断"我应该从哪里获取知识"的四维评估框架。核心思想是：信息源的质量决定了你知识体系的质量——垃圾进，垃圾出。

**四个维度**：
1. **一手段位**: 信息离原始创造者越近越好。原始论文 > 官方文档 > 作者本人的书 > 权威教材 > 二手解读 > 自媒体文章。每经过一次"中间人"，信息就可能失真甚至被篡改（"中间人攻击"）
2. **可验证性**: 好的信息提供数据、引用、实验结果，你可以独立检验其真实性。无法验证的信息只能"信或不信"，不是知识
3. **时间检验**: 存在了10年以上的知识比刚火起来的"热点"更可靠。基础知识（算法、操作系统原理、网络协议）经得起时间检验，框架教程可能半年就过时
4. **信息密度**: 这是最反直觉的维度。好信息不是让你轻松读完的，而是让你读完后想搜索更多、想做实验验证、想找人讨论的。如果一篇技术文章你5分钟就读完了而且毫无疑惑，说明它的信息密度太低

## A1 — 书中的应用 (Past Application)

### 案例 1: 从Java到C++到C的逆向学习链
- **问题**: 作者学Java时发现书中有大量C++知识不懂，需要决定信息源
- **方法论的使用**: 用"一手段位"原则——不找二手Java教程，而是去读C++和C的原始经典著作（《C++ Primer》《C程序设计语言》）。这些是语言发明者或顶级专家的一手资料，信息密度极高
- **结论**: 追溯到最源头的一手资料学习，而非停留在二手解读
- **结果**: "C-C++-Java"整条线路融会贯通，学习新技术时可以直奔高级特性，理解编程语言的本质

### 案例 2: 在亚马逊与Principal SDE级别工程师交流
- **问题**: 作者需要在亚马逊快速提升技术思维
- **方法论的使用**: "一手段位"不限于书，人也分一手二手。Principal SDE级别的工程师是"一手信息源"——他们亲历了系统从0到1的设计决策，而非转述别人的经验。与高手交流获得的"信息密度"远超普通同事
- **结论**: 找一手信息源不仅限于阅读，还包括与人交流
- **结果**: "无论与高手交流什么都有收获，我的技术思维有了质的提升"

### 案例 3: 2016年选择可观测性作为创业方向
- **问题**: 需要判断可观测性在国内的市场时机
- **方法论的使用**: 用"时间检验"维度——可观测性在国外已经火了很长时间，经过了大公司的生产验证。"一手段位"——关注国外的原始实践而非国内的二手解读
- **结论**: 关注一手信息源（国外前沿实践），而非二手信息（国内跟风文章），可以获得时间差优势
- **结果**: 抢在国内走热之前布局，验证了信息源领先的商业价值

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **选择学习资料** — 面对一堆推荐书单/课程/教程，不知道该挑哪个，想判断哪些是高质量信息源
2. **验证一个技术说法** — 看到一篇技术文章提出某个观点（如"微服务比单体好"），想判断其可靠性
3. **构建个人信息源体系** — 想建立自己的RSS/邮件订阅/关注列表，需要评估哪些信息源值得长期跟随
4. **帮团队成员提高学习质量** — 团队成员学习效果差，怀疑是信息源的问题
5. **面试中快速判断候选人水平** — 通过候选人引用的信息源（一手还是二手、有无信息密度）判断其真实水平

### 语言信号 (用户的话里出现这些就应激活)

- "这本书/这篇文章/这个课程值不值得看？"
- "为什么我学了很多但感觉没学到东西？"
- "怎么判断XX说法靠不靠谱？"
- "有哪些靠谱的学习资源推荐？"
- "我看的都是中文资料/公众号文章..."
- "这个人的观点可信吗？"

### 与相邻 skill 的区分

- 与 `five-step-thinking` 的区别: 本skill是信息源的**事前筛选**（用哪个来源），five-step-thinking 是信息内容的**事后分析**（用五步法判断具体说法的真伪）
- 与 `tech-selection` 的区别: 本skill评估的是信息/知识来源的质量，tech-selection 评估的是技术产品的市场成熟度
- 与 `deep-learning-trio` 的区别: 本skill是"采集"环节的具体工具（判断采什么），deep-learning-trio 是完整的"采集-缝合-转换"流程

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

0. **前置检查：确认评估范围和用户水平**
   - 完成标准: 明确用户要评估的**单个信息源**还是**信息源体系**，以及用户当前的学习阶段
   - 判断逻辑:
     - 如果用户说"我看了一本书/文章" → 单源评估模式，进入步骤1
     - 如果用户说"我学的都没用/我看的都是XX" → 体系诊断模式，进入步骤1但按多源处理
     - 如果用户是**零基础入门阶段**（明确说"零基础/入门/刚开始学"）→ 切换入门模式：推荐可读性高的二手资源作为起点，给出渐进式升级路径，**不做严格四维度评估**
   - ⏸️ 检查点: 如果信息源不明确，先向用户确认"你想评估的是哪个具体的信息源？"再继续

1. **定位信息源在"一手段位"光谱上的位置**
   - 完成标准: 明确标注当前信息源属于哪个层级，并指出是否有更接近一手的选择
   - 一手段位光谱（从高到低）:
     ```
     ★★★ 原始论文/规范文档/语言发明者著作（如 RFC、K8s design doc）
     ★★☆ 官方文档/权威教材（如 Kubernetes 官方文档、《算法导论》）
     ★☆☆ 专家著作/高质量技术博客（如 Martin Fowler 博客、美团技术团队）
     ☆☆☆ 二手解读/教程/视频课程（如 "XX入门教程"、公众号解读文章）
     ☆☆☆ 自媒体/营销号/付费专栏（如 "21天精通XX"）
     ```
   - 判停条件: 若已经是一手信息源（★★★ 或 ★★☆），跳过此步直接进入步骤3

2. **检验可验证性和信息密度**
   - 完成标准: 逐项检验以下两个维度，给出 ✓/✗ 判定
     - (a) **可验证性**: 信息中是否有可独立验证的数据、引用或实验？有无具体出处（论文名、官方链接、版本号）？
     - (b) **信息密度**: 读完这个信息后，列出至少 3 个它激发你想要进一步搜索/验证/实践的具体问题。如果列不出 3 个，信息密度不够
   - 快速判断: 如果一个信息源你 5 分钟就读完且毫无疑问，大概率信息密度偏低

3. **输出结构化评估报告**
   - 完成标准: 按以下模板输出评估结论

   ```markdown
   ### 信息源评估报告

   **信息源**: [名称]
   **一手段位**: ★★★~☆☆☆（[层级]）
   **可验证性**: ✓/✗ — [一句话说明]
   **信息密度**: ✓/✗ — [一句话说明]

   **综合评级**: ⭐推荐 / ⚠️谨慎 / ❌不推荐
   **一句话理由**: [为什么这个评级]

   **替代推荐**（如评级非"推荐"）:
   - [更高质的信息源名称] — [为什么它更好]
   ```

   ⏸️ 检查点: 如果评级为"不推荐"且用户是初学者，输出前确认："这个信息源对你来说偏难，是否需要推荐入门级的替代品？"

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **纯事实查询**: 查一个API用法、一个命令参数，不需要评估信息源质量，搜索引擎第一条结果通常就够用
- **入门阶段**: 对于完全零基础的学习者，二手信息源（入门教程、视频课程）虽然信息密度低但可读性高，是合理的起点。先入门再追求一手信息
- **时效性信息**: 新闻、版本更新公告等时效性信息，"一手"和"信息密度"标准不适用

### 作者在书中警告的失败模式

- **快餐式学习陷阱 (ce01)**: 用碎片化、被动接收的方式"学习"，产生"我已经在成长"的幻觉。朋友圈、微博、知乎、今日头条、抖音的信息价值极其有限，越学越焦虑，越学越浮躁
- **信息茧房与二手信息陷阱 (ce10)**: 长期依赖二手信息源，信息在传递中失真，导致知识体系存在系统性错误。推荐算法让人只看到"喜欢看"的内容，看不到更广阔的知识版图
- **收藏家陷阱 (ce18)**: 大量收藏"好文章"却从未认真阅读，收藏行为本身提供即时满足感，让人误判为"已经学到了"
- **被动学习陷阱 (ce26)**: 只通过听讲、阅读、看视频等被动方式学习，学习留存率极低（5%-30%）。好信息源应该驱动你主动实践

### 作者的盲点 / 时代局限

- "一手信息"假设用户有足够的基础知识来理解原始论文和官方文档，对初学者来说门槛过高
- 未充分考虑语言壁垒：非英语母语的程序员获取一手信息（通常是英文）的成本远高于二手信息（中文翻译/解读）
- "信息密度"这个维度比较主观，不同水平的人对同一信息源的密度感受不同（对高手来说信息密度高的内容，新手可能觉得不知所云）
- 在AI时代，"一手信息"的定义正在模糊——ChatGPT等工具本身就是"信息蒸馏器"，既非一手也非二手

### 容易混淆的邻近方法论

- 信息源质量 vs 信息内容质量: 本skill评估的是"来源"的可靠性，不评估具体一篇文章的论证质量（后者属于 five-step-thinking 的范畴）
- 一手信息 vs 难信息: 一手信息不一定难（如Python官方Tutorial就很易读），难信息也不一定是一手（如晦涩的学术论文可能是二手解读）
