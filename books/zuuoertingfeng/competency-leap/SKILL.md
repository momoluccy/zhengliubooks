# 竞争力四步跃迁模型

## R — 原文 (Reading)

> "普通人想要超过他人，应主要培养两种能力：一是在工作领域立足的能力，包括认知、知识和技能；二是在工作领域领跑的能力，包括领导力。通过学校、培训或书本，'零散的认知'被转化为'系统的知识'，而将知识转化为技能则需要通过训练和实践。对技能提高标准，以拉开自己和其他人的差距，也就形成了领导力。"
>
> — 陈皓, 第5章 有竞争力的程序员

---

## I — 方法论骨架 (Interpretation)

这个模型将个人竞争力的发展分解为四个递进阶段，每一步之间有质的门槛，而且"每一步都会过滤掉大量人"。

1. **认知**：获取优质信息、开阔眼界。不是"知道很多"，而是能甄别信息质量、理解事物本质。核心动作是接触一手资料和高质量信息源，而非被动接受投喂。
2. **知识**：将零散认知转化为系统的知识树。不是堆砌知识点，而是建立知识之间的逻辑关联（因果、层级、类比），形成可索引、可扩展的结构。
3. **技能**：通过训练和实践将知识内化为可重复的能力。关键不是"做过了"，而是"精益求精"和"找高手切磋"——持续提高标准直到拉开与他人的差距。
4. **领导力**：在技能基础上建立影响力。不是管理头衔，而是通过解决他人无法解决的问题、提供思路和方案、做出正确决策来获得团队认可。

核心洞察：这四步不是"多学就行"的线性积累，每步之间有质的飞跃要求。从认知到知识需要系统化思维，从知识到技能需要大量实践，从技能到领导力需要提高标准并产生影响力。

## A1 — 书中的应用 (Past Application)

### 案例 1: 从银行辞职到互联网——从零开始的认知跃迁
- **问题**: 作者1998年在银行工作，技术含量低、发展空间有限，面临"继续安稳"还是"出去闯"的选择。
- **方法论的使用**: 主动追求更高层级的"认知"——投身互联网大潮，从昆明到上海再到北京，接触更前沿的技术信息源和工作环境。这个过程中信息源质量从银行内部系统跃迁到互联网行业前沿。
- **结论**: 选择比努力更重要，但选择也更难——需要清晰的目标和承担风险的勇气。
- **结果**: 虽然起步艰难（上海互联网泡沫期间面试屡屡碰壁），但最终进入汤森路透、亚马逊、阿里等顶尖公司，认知层的跃迁是后续所有发展的起点。

### 案例 2: 在亚马逊与Principal SDE级别以上工程师交流——技能到领导力的跨越
- **问题**: 作者在亚马逊已经有不错的技术能力，但需要从"个人技术强"跃迁到"有技术领导力"。
- **方法论的使用**: 遵循"找高手切磋"的原则，主动与美国Principal SDE级别以上的资深工程师交流。通过高标准的互动，体验"技术思维质的提升"——这正是第四步"领导力"的入门路径。
- **结论**: "无论与高手交流什么都有收获"——技能标准只有在与顶尖者对比时才能被拉高。
- **结果**: 技术思维有了质的提升，形成了"找高手切磋是提升技能的捷径"的方法论，后来成为技术领导力四支柱模型的重要来源。

### 案例 3: 40岁靠技术能力养活家庭和团队——领导力的终极验证
- **问题**: 40岁时辞去高薪工作，不加入任何公司、不动积蓄、不接受投资，需要靠纯技术能力生存。
- **方法论的使用**: 这是对四步跃迁终极成果的验证——前三步（认知+知识+技能）积累到一定程度后，第四步"领导力"体现为"不依赖任何组织，仅凭技术实力就能创造价值"。
- **结论**: 真正的技术能力是无法用绩效数字来证明和衡量的。
- **结果**: 成功通过技术服务养活家庭并聘请3名工程师，这段经历也成为创业MegaEase的前奏。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户是工作2-5年的程序员，感觉每天都在做重复的CRUD，不知道怎么提升到"有竞争力"的水平——需要判断自己卡在哪个阶段。
2. 用户想从纯执行者成长为有技术影响力的人（比如想成为Tech Lead或架构师），但不知道从"技术好"到"有领导力"之间缺什么。
3. 用户面临职业转型（如从前端转后端、从开发转架构），需要规划一条系统的提升路径而非盲目学习。
4. 用户在团队中技术能力不错但不被重视，不知道如何从"技能强"跃迁到"有影响力"。

### 语言信号 (用户的话里出现这些就应激活)

- "我该怎么提升竞争力/怎么脱颖而出"
- "感觉遇到了瓶颈/天花板"
- "工作几年了还是感觉没什么核心竞争力"
- "怎么从技术好变成有影响力"
- "该学什么才能突破现在的水平"

### 与相邻 skill 的区分

- 与 `deep-learning-trio` 的区别: 本skill是"竞争力的四阶段发展路径"，回答"我该往哪走"；deep-learning-trio 是"单个知识点从输入到内化的三步法"，回答"我该怎么学"。本skill的第二步"知识"和第三步"技能"会用到 deep-learning-trio 的方法。
- 与 `five-step-thinking` 的区别: 本skill是职业发展框架，关注"我的竞争力在哪里、怎么提升"；five-step-thinking 是通用思考方法，关注"这条信息/主张是否可信"。本skill第一步"认知"的核心工具是 five-step-thinking。
- 与 `tech-learning-sop` 的区别: 本skill是宏观的职业发展路径，tech-learning-sop 是微观的"如何系统学习一项具体技术"。tech-learning-sop 是本skill第二、三步中可用的工具之一。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断当前阶段 — "你现在卡在哪一步"**
   - 通过提问判断用户处于四步中的哪一步：如果用户说"不知道学什么"→卡在认知（信息源不足）；如果"学了很多但无法系统化"→卡在知识（没有知识树）；如果"理解了但不会做"→卡在技能（缺少实践）；如果"做得到但不被认可"→卡在领导力（缺少影响力）。
   - 完成标准: 明确标注用户当前所处阶段（认知/知识/技能/领导力），并列出该阶段的核心差距。
   - 输出格式:
     ```
     ## 竞争力阶段诊断
     | 阶段 | 状态 | 核心差距 |
     |------|------|----------|
     | 认知 | ✅已通过 / ⚠️当前卡点 / 🔲未到达 | … |
     | 知识 | ✅已通过 / ⚠️当前卡点 / 🔲未到达 | … |
     | 技能 | ✅已通过 / ⚠️当前卡点 / 🔲未到达 | … |
     | 领导力 | ✅已通过 / ⚠️当前卡点 / 🔲未到达 | … |

     **当前卡在**: [阶段名称]
     **判断依据**: [1-2句话说明为什么判定卡在这一步]
     ```

   ⏸️ **检查点**: 诊断结果输出后，暂停向用户确认：诊断是否符合自己的实际情况？是否同时卡在多个阶段？确认后再进入步骤2制定目标。

2. **制定阶段目标 — "这一步做到什么程度才算通过"**
   - 认知阶段：目标是从二手信息源跃迁到一手信息源，能够甄别信息质量。指标：能否列出3个高质量的一手信息来源。
   - 知识阶段：目标是建立系统知识树而非碎片化记忆。指标：能否用一棵树画出当前领域的知识结构，并标注每个节点之间的关系。
   - 技能阶段：目标是通过实践和与高手切磋来提高标准。指标：能否解决该领域80%的实际问题，并能说出"还有哪些做不好"。
   - 领导力阶段：目标是在团队中成为"被主动咨询的人"。指标：是否有人因你的技术方案而改变了做法。
   - 完成标准: 为用户当前阶段给出1个具体目标和1个可衡量的完成指标。

3. **规划下一步行动 — "从当前阶段到下一阶段需要做什么"**
   - 给出从当前阶段到下一阶段的具体行动清单（不超过3项）。
   - 判停条件: 如果用户同时卡在多个阶段，优先解决最早卡住的阶段——因为后面的阶段依赖前面的基础。跳阶段会导致"空中楼阁"。
   - 完成标准: 输出一张包含"当前阶段→目标→行动项→完成指标"的四行表。
   - 输出格式:
     ```
     ## 行动规划表
     | 当前阶段 | 目标 | 行动项（≤3项） | 完成指标 |
     |----------|------|----------------|----------|
     | [阶段名] | [1句话目标] | 1. … 2. … 3. … | [可衡量指标] |

     **推荐配合skill**: [根据阶段推荐对应的skill，如认知→info-source-quality，知识→deep-learning-trio，技能→tech-learning-sop]
     ```

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **需要立即解决的具体技术问题**: 用户问"怎么修这个Bug""如何优化这个SQL"，这是具体技能问题，不涉及竞争力发展路径。
- **非技术职业路径**: 模型基于程序员/技术人的发展路径，对产品经理、设计师等非技术角色的适用性有限。
- **追求安逸的选择**: 如果用户的目标是"少做事多拿钱"而非"提升竞争力"，这个模型不适用——它的底层假设是持续成长。

### 作者在书中警告的失败模式

- **投机者心态 (ce05)**: 追求短期利益和"捷径"而非积累核心竞争力。"投机者热衷于在职场上讨好领导，在学习上追求速成。"——竞争力跃迁的四步没有捷径，每步都需要时间和精力的投入，试图跳过某步直接到下一步会走弯路。
- **快餐式学习陷阱 (ce01)**: 用碎片化方式"学习"产生成长幻觉。"越学越焦虑，越学越浮躁。"——这恰好是卡在"认知"阶段但误以为已经在"知识"阶段的典型症状。
- **35岁危机的自我实现预言 (ce17)**: 相信"程序员35岁就没用"而放弃技术深耕，在应该从"技能"跃迁到"领导力"的阶段选择了退出。"30岁是编程的起点，而不是终点。"
- **舒适区陷阱 (ce21)**: 在舒适区中待太久，能力单一化。"选择安逸"意味着停留在某个阶段不再前进，温水煮青蛙式退化。

### 作者的盲点 / 时代局限

- 模型基于互联网行业经验，"每步都会过滤掉大量人"的假设在传统行业（如嵌入式、工业软件）可能不成立——这些领域的前三步门槛不同，且"领导力"的定义也不同。
- 存在幸存者偏差：作者成功走完了四步，但大量同样努力的人可能因为结构性因素（经济周期、行业政策）而未能跃迁。模型假设"只要做到X就能跃迁"，但现实中跃迁还依赖时机和运气。
- 对"领导力"的定义偏技术精英视角——"解决他人无法解决的问题"要求极高的技术天赋，对大多数普通程序员来说，更务实的领导力可能是"带领团队稳定交付高质量产品"。

### 容易混淆的邻近方法论

- "T型人才"模型强调"先深后广"，本模型强调的是"四步递进"——前者是知识结构，后者是能力发展的时序路径。
- "一万小时定律"强调的是"技能"阶段的刻意练习，本模型则指出技能只是四步中的一步，且之前的"认知"和"知识"是技能的前提。
