# 做正确的事的决策框架

## R — 原文 (Reading)

> 推动自己和身边的人持续进步，坚持做正确且有价值的事情，不惧怕被开除。五条标准：1)追求长期收益而非短期利益；2)追求质的成长而非量的增长；3)提高效率而非降低效率；4)解放生产力而非限制生产力；5)增强竞争力而非削弱竞争力。
>
> — 陈皓, 第4章 做正确的事，等着被"开除"

---

## I — 方法论骨架 (Interpretation)

这是一个用于判断"一件事值不值得做"的五条标准 checklist，核心思想是：做推动进步的事，即使有摩擦。

1. **长期收益**：这件事的回报在一年后仍然有效吗？还是只在当下有用？
2. **质的成长**：做这件事能让你的能力发生质变（而非量的堆叠）吗？
3. **提高效率**：做完后，单位时间的产出会变高吗？
4. **解放生产力**：做完后，人能从重复劳动中解放出来吗？
5. **增强竞争力**：做完后，你的不可替代性会提升吗？

使用方式：对候选行动逐条打勾，通过3条以上就值得做。但关键不只是判断，还有**执行的勇气**——正确的事往往伴随摩擦（有人反对、有短期成本），作者的态度是"等着被开除也要做"。

配套行动清单包括：积极推动自动化测试、代码审查、技术分享、消除技术债、建立高效流程等具体实践。

## A1 — 书中的应用 (Past Application)

### 案例 1: 降薪降职加入亚马逊
- **问题**: 作者在汤森路透已是重点培养对象，薪资和职位都不错，面临"安于现状 vs 求变"的选择
- **方法论的使用**: 用五条标准检验——长期收益（亚马逊的工程实践是行业标杆）通过；质的成长（从传统金融技术到互联网大规模系统）通过；增强竞争力（亚马逊经验在简历上极有价值）通过。虽然短期降薪降职，但五条中至少三条通过
- **结论**: 正确的事值得做，即使短期有代价
- **结果**: 在亚马逊学到5-Why分析、数据驱动决策、代码全员开放等核心工程实践，成为后续创业和管理理念的基础

### 案例 2: 创业时拒绝迁就客户的做事方式
- **问题**: 创业期间客户提出不合理的技术方案要求，迁就客户可以拿到短期收入
- **方法论的使用**: 迁就客户→降低效率（后续维护成本高）、限制生产力（被迫用差的技术方案）、削弱竞争力（做出来的东西没有技术含量）。三条不通过，不迁就
- **结论**: 坚持专业判断，把真实想法告诉客户
- **结果**: 虽然沟通成本更高，但建立了更好的合作关系，帮助客户成长而非仅仅完成项目

### 案例 3: 40岁辞去高薪工作仅靠技术服务养活团队
- **问题**: 39岁时父亲病危、工作压力大，面临"留在阿里拿高薪 vs 出来做自己的事"的选择
- **方法论的使用**: 留在阿里→短期收益但不推动质的成长（重复已知领域）；独立做技术服务→质的成长（独立生存能力）、解放生产力（不依赖特定公司）、增强竞争力（可验证的技术实力）。后者的长期价值远高于前者
- **结论**: 不加入任何公司，不动积蓄，仅靠解决技术难题养家并聘请3名工程师
- **结果**: 成功验证了"真正的技术能力不依赖特定公司资源"，直接催生了MegaEase创业

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **技术方案争议** — 团队讨论技术方案时，有人主张"先用最快的方式上线"，有人主张"要做对做好"，用户需要判断哪条路更正确
2. **职业选择犹豫** — 拿到两个offer：一个大厂高薪但做内部工具，一个小公司降薪但做核心技术，不知道怎么选
3. **要不要推动流程改进** — 发现团队没有代码审查、没有自动化测试，想推动但担心同事抵触、领导不支持
4. **技术债困境** — 系统已经千疮百孔，业务方催功能，团队在"还债"和"堆功能"之间摇摆
5. **上级要求做明显错误的事** — 领导要求用某个不合适的技术方案或跳过测试直接上线

### 语言信号 (用户的话里出现这些就应激活)

- "我知道应该做X，但是..."
- "值不值得花时间做这件事？"
- "领导让我做X，但我觉得不对"
- "是该先还技术债还是先做新功能？"
- "这样做有没有长期价值？"
- "我想推动X但怕得罪人"

### 与相邻 skill 的区分

- 与 `tech-selection` 的区别: 本skill是通用的"做不做"决策框架，判断的是行动的价值；tech-selection 是"选哪个"的评估框架，判断的是技术产品的成熟度
- 与 `career-three-goals` 的区别: 本skill聚焦于具体一件事的价值判断（微观决策），career-three-goals 聚焦于职业大方向的阶段规划（宏观路径）
- 与 `time-value-invest` 的区别: 本skill判断"做不做"，time-value-invest 判断"时间投到哪里"

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列出候选行动并逐条检验五条标准**
   - 完成标准: 每条标准有明确的"通过/不通过"判断和一句话理由
   - 判停条件: 若候选行动连2条标准都通不过，直接建议"不做"，跳到步骤3
   - 输出格式:
     ```
     ## 五条标准检验
     | 标准 | 判断 | 理由 |
     |------|------|------|
     | 1. 长期收益 | ✅通过 / ❌不通过 | … |
     | 2. 质的成长 | ✅通过 / ❌不通过 | … |
     | 3. 提高效率 | ✅通过 / ❌不通过 | … |
     | 4. 解放生产力 | ✅通过 / ❌不通过 | … |
     | 5. 增强竞争力 | ✅通过 / ❌不通过 | … |
     **通过数**: [X]/5 → [X≥3 则"值得做" / X<3 则"建议不做"]
     ```

   ⏸️ **检查点**: 五条标准检验完成后，暂停向用户确认：每条标准的判断是否客观？是否有"自己想通过而硬找理由"的倾向？通过数<3时，用户是否仍想做？确认后再进入步骤2评估摩擦。

2. **评估摩擦成本和执行策略**
   - 完成标准: 列出推动这件事会遇到的主要阻力（人的因素、时间因素、资源因素），并给出"如何带着摩擦前进"的具体策略（如先做小范围试点、用数据说服、找同盟者）
   - 判停条件: 若摩擦成本远大于收益（如会被直接开除且没有后路），建议先积累筹码再推动
   - 输出格式:
     ```
     ## 摩擦评估
     | 阻力类型 | 具体表现 | 应对策略 |
     |----------|----------|----------|
     | 人的因素 | … | 先找同盟者 / 用数据说服 / … |
     | 时间因素 | … | 小范围试点 / 分阶段推进 / … |
     | 资源因素 | … | 用最小资源验证 / … |
     **摩擦-收益比**: 高/中/低
     **建议**: [带着摩擦前进 / 先积累筹码 / 放弃]
     ```

3. **给出最终建议和下一步行动**
   - 完成标准: 一个明确的"做/不做/延后"建议 + 一个可以在24小时内启动的具体行动项
   - 输出格式:
     ```
     ## 最终建议
     **建议**: ✅做 / ❌不做 / ⏳延后
     **理由**: [1-2句话]

     ### 下一步行动（24小时内可启动）
     - **行动项**: [具体做什么]
     - **预期结果**: [完成后的状态]
     - **配合skill**: [如涉及技术标准→tech-selection，涉及时间投入→time-value-invest]
     ```

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **生存期决策**: 当个人或团队处于生存危机（如现金流断裂边缘）时，短期利益高于一切，不应套用长期主义框架
- **高度不确定的创新探索**: 在完全没有数据支撑的早期探索阶段，五条标准可能全部"不确定"，强行打分会制造虚假的确信感
- **纯审美/偏好类选择**: 如代码风格、技术栈偏好等主观选择，不存在"正确"与否

### 作者在书中警告的失败模式

- **长期妥协陷阱 (ce12)**: 偶尔妥协是策略，但每次都妥协就成了习惯。第一次妥协降低了标准，第二次有"上次也妥协了"的先例，心理门槛越来越低，最终个人能力停滞、公司也没有进步
- **加班思维陷阱 (ce09)**: 用加班（体力投入）替代思考（智力投入），代码质量下降导致故障频发，形成恶性循环。正确的事不是"加班赶工"，而是"用制度保障质量"
- **为逃避而选择 (ce03)**: 如果选择的动机是"逃离当前困境"而非"追求某个目标"，到了新环境问题依旧甚至更多。正确的事必须以"追求什么"为起点，而非"逃离什么"
- **迁就技术债的恶性循环 (ce08)**: 不还债继续堆功能，债越积越多。"长痛不如短痛"，与其花大力气迁就技术债，不如直接还清

### 作者的盲点 / 时代局限

- "等着被开除"的勇气建议基于作者本人有顶尖技术实力作为后盾，对普通程序员来说风险远大于收益
- 五条标准隐含了"有选择权"的前提——当经济下行、就业困难时，很多人没有资格谈"长期收益"
- 未考虑组织政治的现实：在部分公司中"做正确的事"可能被解读为"不服从管理"，后果不仅是被开除，还可能影响行业声誉
- 幸存者偏差：作者做对了选择并成功了，但同样坚持"做正确的事"而被边缘化的人不在少数

### 容易混淆的邻近方法论

- "做正确的事" vs "把事做正确": 前者是决策层面（选什么），后者是执行层面（怎么做）。本skill只解决前者
- "做正确的事" vs "做安全的事": 正确的事往往有摩擦和风险，安全的事是回避冲突。作者明确主张前者
